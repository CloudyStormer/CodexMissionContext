# aidrama

把故事材料转化为可重复执行的 AI 漫剧生产包。保留用户的创作意图，明确标注工作假设，并让每项素材都能从剧情节拍追溯到具体镜头。

## 判断当前任务

先识别用户需要完成哪个生产阶段，只补齐必要的上游工作：

- 开发创意：建立项目简报、一句话故事、观众承诺、世界规则和连载方向。
- 改编原作：保留关键人物、因果关系和标志性情节，再按目标平台与时长重组。
- 制作单集：完成单集目标、节拍表、制作剧本、分镜表、生成提示词、配音字幕稿和质检报告。
- 修订单集：先判断问题属于剧情、节奏、画面、连续性还是制作可行性，再修改受影响的文件。
- 检查交付包：验证结构、时长、连续性、提示词完整性和交付状态。

用户只要一个文件时，不要强行执行整条流水线。项目已经存在时，先读取既有设定，不要暗中替换已确认事实。

## 按需读取资料

- 进行创意开发、原作改编、节拍设计或剧本写作时，读取 [故事生产规则](references/故事生产规则.md)。
- 创建角色卡、分镜表、图片或视频提示词，或者检查一致性时，读取 [视觉连续性](references/视觉连续性.md)。
- 整理单集交付包、验证文件或制作质检报告时，读取 [交付质检](references/交付质检.md)。
- 新建交付文件时，从 `assets/` 复制相应模板后再填写，不要直接修改技能内的原始模板。

只读取当前任务需要的资料，避免把无关规则全部加载进来。

## 建立项目简报

整理用户已经提供的信息：

- 原始故事材料及权属背景
- 目标观众与发布平台
- 语言、画幅、单集时长、集数与更新频率
- 类型、语气、视觉风格和参考作品
- 使用工具、预算、时间和内容边界
- 所需交付物与审批节点

每次最多询问一个真正阻塞的问题。用户希望快速开始时，采用合理默认值继续，但必须把默认值写入“工作假设”。用户明确提供的信息始终优先。

## 执行生产流程

### 1. 锁定项目基础

创建或更新项目简报。明确一句话故事、观众承诺、主角欲望、核心阻力、失败代价、连载驱动力、视觉方向、制作限制和验收标准。

### 2. 建立故事与连续性设定库

定义世界规则、人物目标、人物关系、外观锁定、常驻场景、关键道具、时间线事实和禁止变化。给长期复用的对象分配稳定编号。

### 3. 设计单集

明确本集的核心戏剧问题与观众回报。编排开场钩子、矛盾升级、关键转折、情绪或剧情回报，以及结尾悬念。确认计划时长能够容纳这些节拍。

### 4. 编写制作剧本

分别写清可见动作、对白、旁白、屏幕文字、音效和音乐提示。保证台词可以自然说出口，并标记每个新增人物、服装、场景、道具和连续性状态。

### 5. 拆分制作镜头

按照 `assets/分镜表模板.csv` 的字段，每个镜头填写一行。每行都使用完整且唯一的镜头编号，例如 `第001集-镜头002`；不得缩写为 `镜头002`。写清时长、景别、机位、画面、动作、对白或旁白、图片提示词、视频提示词和连续性引用。

### 6. 编写生成提示词

把提示词拆成可以复用和检查的部分：

- 已锁定的人物、场景和系列画风
- 当前镜头的构图、动作和情绪
- 视频动作节奏与镜头运动
- 禁止变化与负面约束
- 参考素材编号

提示词必须面向生产，避免只写文学描写。没有实际调用生成工具时，不得声称图片、视频或声音已经生成。用户要求生成素材时，先读取相应图片、视频、音频或浏览器技能的完整规则。

### 7. 执行质量检查

检查剧情因果、开场钩子、目标时长、人物外观、服装、道具、空间关系、光线、提示词完整性、台词时长、字幕可读性和交付结构。把阻塞问题与优化建议分开报告。

### 8. 整理交付

交付时包含：项目概况、工作假设、已确认事实、未决问题、文件清单、缺失素材、阻塞问题和推荐的下一步。跨版本保持文件名与编号稳定。

## 使用标准项目结构

创建新项目：

```bash
python3 scripts/初始化项目.py --项目名 "项目名称" --输出目录 "/目标父目录"
```

标准目录：

```text
项目名称/
├── 00-项目简报/
├── 01-设定库/
├── 02-单集/
│   └── 第001集/
├── 03-素材/
│   ├── 参考资料/
│   ├── 图片/
│   ├── 音频/
│   └── 视频/
└── 04-交付/
```

检查已填写的分镜表：

```bash
python3 scripts/校验分镜表.py "/分镜表路径/分镜表.csv"
```

脚本报错属于阻塞问题；脚本警告需要结合制作判断进行复核。

## 持续沉淀业务规则

把本技能中的规则视为可编辑的业务默认值，而不是永远不变的真理。真实项目中反复验证有效的剧情节奏、画风规范、平台要求、提示词结构、模板和质检阈值，应逐步沉淀到对应资料或模板中。只属于单个项目的临时事实不要写回技能。
