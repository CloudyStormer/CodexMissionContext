# 每日项目同步

每天只完成两项工作。若用户发送四字口令“开始同步”，立即交给 `check-projects` 的完整同步模式处理；本 Skill 不与该口令竞争。

全部仓库操作由当前同步任务统一执行，不逐项目创建或唤醒独立任务，也不逐仓要求用户确认。用户的一次每日同步或交接口令已经授权本 Skill 内允许的普通 Git 操作；若平台仍强制交互授权，完成其余可执行部分后只汇总一次阻塞，不连续发起确认。

## 一、汇总今天的侧边栏任务

1. 先拉取 `D:\.aaProject-Bruce\CodexMissionContext` 的最新远端上下文。
2. 读取 Codex 侧边栏中今天更新的任务；优先使用任务标题、概述和最终回复。只有概述不足时，才读取该任务最近一轮，不回看整段对话。
3. 按项目归组，写入或更新 `每日同步/YYYY-MM-DD.md`：
   - 项目与任务名称
   - 今天完成的工作
   - 提交、推送或交付状态
   - 唯一阻塞和下一步
4. 只保存精准压缩总结，不保存原始对话、密码、令牌、Cookie、私钥或本地会话数据。

## 二、同步共同项目代码

范围由 Codex 当前侧边栏的本地项目列表决定；`同步清单/项目清单.md` 用于识别共同项目和优先级，但不排除侧边栏内其他 D 盘项目。Windows 只处理 `D:\.aaProject-Bruce\` 下的项目，不扫描侧边栏之外的 D 盘目录。项目根目录不是 Git 仓库时，只检查其根目录和直接子目录中的 Git 仓库。

对清单内每个实际 Git 仓库依次执行：

1. 检查分支、上游和简短状态，不分析逐文件业务差异。
2. 获取远端并同步当前分支；无本地改动时优先快进拉取。
3. 根据侧边栏任务的完成结论，只提交任务已经确认可交付的本地改动。
4. 推送当前分支，并验证本地 `HEAD` 与上游一致。
5. 已一致且没有可交付改动时，记录“已同步”，不制造空提交。

## 轻量安全边界

- 不人工逐文件复盘，不做额外视觉检查、业务测试或内容研究；具体任务已明确要求的验证除外。
- 不把仍在运行、明确排除或尚未确认可交付的改动混入每日提交。
- 提交前只做基础检查：冲突标记、`git diff --check`、敏感文件名和异常大文件。
- `.env`、密钥、Cookie、数据库、缓存、会话文件和本机账号状态永不提交。
- Windows 共同项目只使用 `D:\.aaProject-Bruce\` 下的保存项目，不在 C 盘创建项目副本或 worktree。
- 拉取冲突、缺少远端、推送失败或任务仍在运行时，准确记录并停止该仓库，不猜测完成。

## 收尾

最后检查共同上下文仓库，提交并推送当天报告。对用户只汇报：

- 已同步的项目
- 对应分支和提交
- 未同步项目及唯一原因
- 是否可以在另一台设备直接继续
