# skillnotes

把本技能中的主题笔记视为长期学习记忆的事实来源。笔记保存的是提炼后的稳定结论，不是聊天记录入口。

## 坚守核心原则

- 不通过对话链接、任务编号、线程历史或聊天搜索找回知识。
- 不默认读取旧对话；直接读取已经整理好的主题笔记。
- 不把当前模型印象或未写入笔记的内容冒充历史记忆。
- 没有记录时明确回答“学习笔记中尚未记录”。
- 只有用户明确要求“记下来、加入笔记、更新笔记”时才修改文件。

## 先读取索引

始终先读取 [学习索引](references/学习索引.md)，再判断下一步：

- 回忆全部：只使用索引中的一句话摘要；用户要求展开时再读取相关主题文件。
- 回忆单个主题：根据主题名或别名，只读取索引指向的一个主题文件。
- 比较多个主题：只读取被点名的主题文件。
- 总结当前对话：使用当前上下文直接整理，不搜索历史对话。
- 记录当前学习：整理当前上下文，写入一个主题文件并同步更新索引。

不要遍历或一次性读取所有主题文件。

## 回忆主题

1. 在索引中优先匹配完整主题名。
2. 没有完整匹配时，匹配别名和关键词。
3. 读取命中的主题文件。
4. 按用户要求控制长度，默认先给一句话，再给 3–6 个关键结论。
5. 涉及当前安装状态时，可以检查对应对象的实时元数据，但不要改写历史记录。
6. 历史笔记与当前状态不一致时，分别标明“笔记记录”和“当前状态”。

默认回答格式：

```text
主题：
一句话回忆：
关键结论：
能力边界或常见误区：
下一步：
```

## 回忆全部

只读取索引并输出：

1. 已记录主题数量。
2. 每个主题的一句话记忆。
3. 最近更新日期。
4. 用户指定后再展开某个主题。

不要为了“回忆全部”加载所有主题全文。

## 总结并记录当前学习

用户明确要求记录时：

1. 只使用当前对话中已经出现的学习内容，不寻找其他对话。
2. 接受用户指定的主题名；未指定时，用 2–12 个字概括主题。
3. 将聊天内容压缩成稳定知识，删除寒暄、重复解释、工具日志和临时过程。
4. 不保存原始对话链接、任务编号、聊天全文或用于回溯聊天的指针。
5. 保留已经验证的结论、操作方法、能力边界、失败经验和记忆钩子。
6. 新主题写入 `references/主题-主题名.md`；同主题的新学习合并到原文件，避免重复创建。
7. 更新 `references/学习索引.md` 中的主题名、别名、一句话摘要、日期和文件路径。
8. 写入完成后，向用户展示新增或修改了哪些要点。

主题笔记统一采用：

```text
# 学习主题：主题名
记录日期：
最近更新：

## 一句话回忆
## 为什么重要
## 核心结论
## 怎么使用
## 能力边界与误区
## 已验证记录
## 下次回忆提示
```

根据主题实际内容删去无用小节，不为凑格式制造空内容。

## 控制笔记质量

- 使用中文，技能名、命令、路径和规范文件名保留原样。
- 一个知识点只保留一个权威表述。
- 区分事实、用户偏好、工作假设和未来计划。
- 优先记录能跨任务复用的知识。
- 单个主题尽量控制在 200 行以内；过长时拆成新的独立主题，并在索引中建立关联。
- 不记录密码、令牌、私人通信、敏感身份信息或未经允许的个人资料。
