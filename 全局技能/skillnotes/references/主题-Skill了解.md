# 学习主题：Skill了解

记录日期：2026-07-27  
最近更新：2026-07-27

## 一句话回忆

技能是可复用的专业工作方法，不是新的模型能力；它通过“描述触发、主文件调度、资料按需读取、模板复用、脚本稳定执行”让 Codex 按固定流程工作。

## 为什么重要

把反复解释的业务知识、工作步骤和验收标准沉淀进技能后，可以跨项目复用；真正有价值的不是下载很多技能，而是把自己的业务方法做成能够验证和迭代的技能。

## 核心记忆公式

```text
description 负责触发
SKILL.md 负责调度
references 提供知识
assets 提供模板
scripts 稳定执行
```

## 技能、MCP 与插件

| 概念 | 核心作用 | 记忆方式 |
|---|---|---|
| 技能 | 封装知识、流程、模板和脚本 | 说明书与操作规程 |
| MCP | 连接外部工具、数据和可执行能力 | 通用接口 |
| 插件 | 打包技能、MCP、连接器、界面和资源 | 整套工具箱 |

安装技能不会凭空增加视频生成、账号登录或外部数据权限。技能可以指导如何使用工具，但工具本身必须真实存在并已授权。

## 调用方式

- `$技能名`：Codex 中明确调用技能。
- `@技能名`：ChatGPT 或桌面端提及入口；当前界面可能与 `$` 共用同一份全局技能。
- 自然语言：请求与 `description` 匹配时可以自动触发。
- 同时能被 `@` 和 `$` 找到，不代表安装了两份；通常只是两个界面入口指向同一技能。

## 全局安装与查看

- 全局技能目录：`~/.codex/skills`。
- 全局技能可被所有本地项目发现。
- Finder 打开：`open ~/.codex/skills`。
- 终端进入：`cd ~/.codex/skills`。
- 单独输入 `~/.codex/skills` 会被终端当作可执行命令，因此出现 `permission denied`。

## 渐进式加载

技能不会默认深度遍历整个目录：

1. 平时只保留 `SKILL.md` 顶部的 `name` 和 `description`，用于判断是否触发。
2. 触发后完整读取 `SKILL.md`，获得总流程和资源导航。
3. 根据任务，只读取需要的 `references`、使用相关 `assets` 或运行相关 `scripts`。
4. 信息足够且任务完成后停止，不继续加载无关文件。

文件名只是路标。真正建立对应关系的是 `SKILL.md` 中明确写出的相对路径和“什么情况下读取”。资源改名后，必须同步修改引用它的主文件或脚本。

## 标准目录

```text
技能名/
├── SKILL.md
├── agents/openai.yaml
├── references/
├── assets/
└── scripts/
```

- `SKILL.md`：必需；顶部负责触发，正文负责流程与路由。
- `agents/openai.yaml`：控制界面显示名称、简短描述和默认提示词。
- `references/`：按需读取的知识、规则和规范。
- `assets/`：复制使用的模板和成品资源。
- `scripts/`：执行重复、机械、容易出错且需要稳定结果的操作。

## 创建自己的技能

1. 明确一个重复任务、典型输入和最终输出。
2. 设计简短、准确的名称和触发描述。
3. 规划主流程以及需要的知识、模板和脚本。
4. 使用标准初始化工具创建骨架。
5. 编写内容并运行结构校验。
6. 用真实任务独立试用。
7. 把发现的问题写回规则，再次验证。

一个复杂业务线可以先做一个总控技能，稳定后再拆成多个子技能或插件。

## 已安装与学习过的技能

| 技能 | 一句话作用 | 关键边界 |
|---|---|---|
| `$skill-installer` | 查看并安装精选或指定仓库中的技能 | 不赋予外部权限，不应无提示覆盖同名目录 |
| `$skill-creator` | 创建、校验和迭代自定义技能 | 必须先定范围，并用真实任务试用 |
| `$playwright` | 从终端驱动独立浏览器自动化网页 | 需要现有 Chrome 登录状态时应使用 Chrome 控制 |
| `$security-best-practices` | 执行语言与框架安全专项审查 | 只有明确要求安全审查时才触发 |
| `$jupyter-notebook` | 创建、编辑和整理可复现 Notebook | 不会自动获得数据源 |
| `$gh-fix-ci` | 排查 GitHub Actions 中失败的检查 | 需要 `gh` 登录，实施修复前要确认 |
| `$aidrama` | 生成中文 AI 漫剧生产包 | 是导演与生产流程，不是视频生成引擎 |
| `$skillnotes` | 从压缩笔记中回忆学习主题 | 不检索旧对话，没有记录就明确说明 |

## aidrama 案例

`$aidrama` 是本次创建的全局 AI 漫剧业务技能：

- 输入：创意、小说、剧本和制作要求。
- 输出：项目简报、设定库、单集剧本、分镜表、图片与视频提示词、配音字幕稿和质检结果。
- 资料：故事生产规则、视觉连续性、交付质检。
- 模板：项目简报、角色卡、单集剧本、分镜表。
- 脚本：初始化项目、校验分镜表。
- 已验证：通过官方结构校验，并用 90 秒竖屏漫剧做过独立试用。
- 已修正：试用发现镜头编号被缩写，随后新增完整编号规则和脚本校验。
- 能力边界：当前没有视频生成工具时，不能直接生成动态视频或声称已有成片。

## 浏览器案例

`$playwright` 适合独立浏览器自动化。本次需要截取用户已经打开的 Chrome 页面并保留登录状态，因此最终改用 Chrome 控制能力完成截图。这说明要根据任务依赖的浏览器状态选择工具，而不是机械使用同一个技能。

## 已验证结论

- 已全局安装：`playwright`、`security-best-practices`、`jupyter-notebook`、`gh-fix-ci`。
- 已全局创建并校验：`aidrama`、`skillnotes`。
- `$aidrama` 已经过一次无上下文试用并根据结果迭代。
- `$skillnotes` 已测试单主题回忆和全部技能汇总。
- 全局技能目录中的 `SKILL.md` 可以通过 Codex 文件链接在右侧打开编辑。

## 能力边界与误区

1. 技能不会让模型凭空获得原本不存在的工具。
2. 技能不会自动拥有外部账号或服务权限。
3. `$playwright` 与已有 Chrome 会话不是同一个使用场景。
4. 文件名不会自动建立路由，必须在 `SKILL.md` 中明确引用。
5. 回忆学习内容应该读取压缩笔记，而不是回溯整段旧对话。
