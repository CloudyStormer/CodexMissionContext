# produce-aimg

把 AIMG 视为一条轻量、可回退的生产流水线，而不是一次性生成一堆文件。调用 `aidrama` 处理故事、剧本、分镜和交付；需要真实出图时读取并调用 `imagegen`。用户看到的目录必须简单，内部安全检查不得变成用户要维护的状态机。

## 执行状态机

`G0` 通过后，故事结构轨与角色视觉轨可按用户明确要求并行；两条轨道必须在 `G5` 前汇合：

```text
原始材料
→ G0 故事逻辑通过
   ├→ G1 全季结构通过 ─────────┐
   └→ G2 共享画风通过 → G3 双主角正脸共同通过 → G4 全部角色高清九宫格逐人通过 ─┤
                                                                                     └→ G5 剧本与分镜就绪
→ G6 静态首尾帧通过
→ G7 无声样片通过
→ G8 声音字幕与正式样片通过
→ G9 批量生产
→ 交付
```

任一门未通过，继续整理不依赖该门的文字，但禁止执行对应下游生成。`G5` 同时依赖 `G1` 与 `G4`；不要把“已生成”写成“已通过”。

## 1. 锁定输入与事实

先读取项目现有文件、用户最新口径、标题、正文、参考图和历史审批记录。区分：

- 用户明确事实：不得擅改。
- 工作假设：写入项目简报并说明理由。
- 未决问题：只有真正阻塞且无法合理假设时才询问，每次最多一个。

用户新修正覆盖旧稿时，保留版本记录并更新所有受影响的世界规则、时间线、知情状态、剧本、分镜和提示词；禁止新旧口径并行冒充有效。

## 2. 通过故事逻辑门

读取 [故事逻辑门](references/故事逻辑门.md)。重生、循环、穿越、记忆不对称题材必须明确：

- 谁触发、什么条件触发、何时回到哪里。
- 谁被重置、谁保留记忆、实体与技能是否跨轮。
- 每个角色在每个阶段知道什么。
- 每个关键事件的原因、结果和新增信息。
- 计数是否差一轮，随机事件是否稳定，干预是否产生蝴蝶效应。

先用通俗语言把故事完整串给用户。用户修正后更新真源并重新审计；用户明确说“开始弄吧”即表示按最新口径继续，不重复询问已确认事实。

## 3. 建立标准项目

读取 [目录与状态规范](references/目录与状态规范.md)。新项目可运行：

```powershell
python scripts/初始化AIMG项目.py --项目名 "项目名称" --输出目录 "目标父目录"
```

标准目录使用 `01_项目总览` 至 `11_交付文件`。候选、失败素材和内部生成过程放入 `11_交付文件/制作历史`；`07_素材资源` 只保留关键帧交付清单和按集的最终关键帧；`10_角色基准图` 只保留已经用户确认的当前 PNG。已有项目只补缺失结构，不为了统一而覆盖或重排用户文件。

全局写透、局部做细：完整故事做到路线图与时间线；首个叙事单元做到分集节拍；首 3 集做到制作剧本与分镜；先正式制作 1 集样片。

## 4. 建共享画风并确认角色

读取 [角色与画风审批](references/角色与画风审批.md)。在分别设计人物前先建立全剧唯一画风圣经，锁定脸部体系、写实度、眼睛比例、皮肤/头发/布料材质、焦段、测试光、色彩和禁止项。

第一轮只生成双主角正脸校准板：同一张图、同一批次、同一背景、同一灯光、同一镜头、同一渲染前缀。两人必须作为一组确认；任一人不通过，整组返工。不得先锁定一人再单独补另一人。

双主角正脸共同通过后，为每个具名或重复出场角色制作一张高清 3×3 九宫格基准图。固定按行排列：正面、背面、角色自身左侧、角色自身右侧、角色自身左前 3/4、右前 3/4、左后 3/4、右后 3/4、正面全身。左右一律以角色自身解剖方向命名，禁止镜像、翻转或只交换标签冒充另一侧。主角九宫格完成后再设计配角，并执行禁止同脸审查。完整协议见 [角色与画风审批](references/角色与画风审批.md)。

当整张自由生成导致眼睛、脸型、服装或方向漂移时，立即停止整图反复重绘：先锁定用户认可的正脸身份卡，再逐格生成并验收九个方向；全部单格通过后，运行 `scripts/合成角色九宫格.py` 做无生成式拼版。拼版只允许裁切、等比缩放、标签和排版，禁止再次生成脸或水平翻转。

G4 必须由用户确认，但确认直接在当前聊天完成。角色可逐人展示，也可整批展示；用户说“过”“通过”“都通过”“就用这个”等无歧义表达，就视为所指角色已确认，不再要求额外表单、状态点击或二次复读。某个角色未通过时只返工该角色，不推翻其他已确认角色。

用户确认前，候选九宫格保留在 `11_交付文件/制作历史/角色生成历史/`，并在聊天中直接披露；不另建待审批目录。用户确认后，将当前 PNG 直接写入 `10_角色基准图/` 根目录，命名为 `角色-XXX_姓名_九宫格.png`。根目录只保留每角色一张当前正式 PNG 和一份 `README.md`，不设版本子目录、`REVIEW/LOCKED` 子目录、manifest 或审批子目录。

## 5. 写入当前角色基准图

外部 AI 图永远先作为候选。用户文字约束高于参考图瑕疵。含纹身、饰品、同脸、风格分裂、畸形或用户禁止项的图不得晋级。

失败图移动到 `11_交付文件/制作历史/角色生成历史/第NN轮_未通过_原因/`，保留失败原因和单变量修法；不得复制到 `10_角色基准图`，不得继续生成侧面、全身或剧情关键帧。

用户明确确认后，使用轻量发布脚本把图片复制到基准图根目录，并写入一份内部确认记录：

```text
10_角色基准图/
├── README.md
├── 角色-001_角色名_九宫格.png
└── 角色-002_角色名_九宫格.png
```

如同一角色以后重做并再次通过，直接替换同名 PNG；不在 10 目录展示旧版。旧生成图仍留在 `11_交付文件/制作历史/角色生成历史/` 供内部追溯。内部确认记录只保留角色、当前路径、用户确认原话和 SHA-256，不要求用户打开、填写或维护。图片哈希变化后必须重新获得用户确认，不能沿用旧原话。

可用脚本执行受控写入：

```powershell
python scripts/创建九宫格清单.py --九宫格 "11_交付文件/制作历史/角色生成历史/第NN轮/候选九宫格.png" --角色编号 "角色-001" --角色名 "角色名" --版本 "v1" --方向已人工复核 --禁止镜像已人工复核
python scripts/确认角色基准图.py --项目 "项目路径" --源九宫格 "项目路径/11_交付文件/制作历史/角色生成历史/第NN轮/当前九宫格.png" --角色编号 "角色-001" --角色名 "角色名" --确认原话 "过"
```

逐格合成时使用：

```powershell
python scripts/合成角色九宫格.py --V01 "正面.png" --V02 "背面.png" --V03 "自身左侧.png" --V04 "自身右侧.png" --V05 "自身左前3比4.png" --V06 "自身右前3比4.png" --V07 "自身左后3比4.png" --V08 "自身右后3比4.png" --V09 "正面全身.png" --角色编号 "角色-001" --角色名 "角色名" --版本 "v1" --项目根目录 "项目路径" --输出 "项目路径/11_交付文件/制作历史/角色生成历史/第NN轮/候选九宫格.png" --方向已人工复核 --禁止镜像已人工复核
```

`确认角色基准图.py` 验证 PNG、角色身份、固定九格和禁止镜像声明，然后安全复制或替换根目录同名图，自动写入精简确认记录。它必须拒绝来自失败目录、非正方形高清 PNG、方向未复核、疑似镜像、角色不匹配或确认原话为空的输入。旧项目的双区目录只读兼容，新项目不再创建或调用。

## 6. 编排剧本与逐 Clip 生产

依次产出项目简报、世界规则、人物关系、时间线和连续性信息。用户可见制作目录默认沿用《差评死神》轻结构：

```text
04_剧集脚本/全季分集脚本.md
05_分镜脚本/全季分镜.md
06_提示词库/统一提示词.md
07_素材资源/第001集关键帧/镜头01.png
07_素材资源/第001集关键帧/镜头02.png
```

`04`、`05`、`06` 各保留一份当前全季文件；`07` 根只保留 `关键帧交付清单.md` 与按集建立的关键帧目录，每个集目录只放最终 PNG。候选、失败稿和中间生成放入 `11_交付文件/制作历史/`，不混入 07。分镜与提示词必须与最终镜头编号一致。

每个 Clip 固定顺序：

```text
连续性锁定
→ 正式首帧
→ 首帧验收
→ 正式尾帧
→ 尾帧验收
→ 仅使用正式帧生成无声草稿
→ 一次只改一个变量
→ 画面锁定
→ 配音、环境声、字幕和剪辑
```

每镜只安排一个主要可见动作。参考图使用“角色名＋精确路径＋本次用途”绑定；多人镜头每名角色只给一张最匹配当前方向的身份参考，避免污染。

## 7. 通过样片门再量产

读取 [生产流水线与质检](references/生产流水线与质检.md)。样片未明确通过，不得批量生成剩余剧集。量产只能复用已验收的画风、角色、声音和镜头合同。

修改会向下游联动：角色、场景、HUD、规则或剧情变化时，检查并更新角色卡、连续性账本、剧本、分镜、提示词、静态帧记录和受影响视频清单。

## 8. 验证与交付

运行：

```powershell
python scripts/校验AIMG项目.py "项目路径"
```

脚本错误是阻塞。交付时报告已确认事实、工作假设、审批状态、文件、实际存在的素材、缺失素材、阻塞和下一步。不得宣称不存在的图、视频、声音已经生成。
