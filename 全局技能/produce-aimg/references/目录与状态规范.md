# 目录与状态规范

```text
项目名/
├── 01_项目总览/
├── 02_世界观设定/
├── 03_角色设定/
├── 04_剧集脚本/
├── 05_分镜脚本/
├── 06_提示词库/
├── 07_素材资源/
├── 08_发布物料/
├── 09_技术文档/
├── 10_角色基准图/
└── 11_交付文件/
```

状态：`DRAFT`、`REVIEW`、`LOCKED`、`REJECTED`、`SUPERSEDED`。只有 `LOCKED` 可进入正式下游。

稳定编号：`角色-001`、`场景-001`、`道具-001`、`第001集`、`第001集-镜头001`、`第001集_clip001`。

候选图按轮次保存；失败图目录必须含“未通过”或“失败”及原因。工作用单格图、原始生成和失败版本留在 `07_素材资源/候选图/`，不冒充正式交付。通过内部 QA、准备送用户审阅的每个角色当前版本，必须将 PNG 与 manifest 实际复制到 `10_角色基准图/角色-XXX_角色名/00_待审批/`；不能用 Markdown 跨目录链接替代图片实体。

正式身份锚点只进 `10_角色基准图/角色-XXX_角色名/01_正式锚点/`。每位角色每个正式版本固定为 `角色基准九宫格_vN.png`、`角色基准九宫格_vN.manifest.json` 和 `审批记录_vN.md`。版本升级使用 `_v1`、`_v2`，不得覆盖旧版；审批记录也必须按版本保存。

```text
10_角色基准图/
├── README.md                         # 用户唯一入口：角色、版本、状态、实际图路径
└── 角色-001_角色名/
    ├── 00_待审批/                   # 当前 REVIEW 实图与 manifest
    ├── 01_正式锚点/                 # 唯一当前 LOCKED 实图、manifest、审批记录
    └── 02_历史锚点/v1/              # 已被替代的 SUPERSEDED 完整旧版本
```

`00_待审批` 与 `01_正式锚点` 都在用户熟悉的角色基准图区，但状态和用途必须物理隔离。审批清单的“候选路径”必须指向对应角色的 `00_待审批` 实体图，“正式路径”必须指向对应角色的 `01_正式锚点`。`01_正式锚点` 每个角色只保留审批清单指向的唯一当前版本；升级前将旧 PNG、manifest 与审批记录整套迁入 `02_历史锚点/vN/`，并把旧 manifest 标为 `SUPERSEDED`。根 README 必须第一屏逐角色列出当前版本及直接打开图片的相对链接；用户不需要去 `07_素材资源` 找送审图。用户审批原话必须同时绑定候选 PNG 的 SHA-256；候选文件、版本或哈希变化时，旧审批不得用于晋级。正式图 SHA 必须等于审批绑定 SHA 与源候选 SHA，正式 manifest 的 `source_candidate`、用户状态和审批原话也必须与审批清单一致。

推荐颗粒度：全局路线图完整，前10集节拍详细，首3集制作包完整，第1集先做样片。
