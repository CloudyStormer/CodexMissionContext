# 技术文档类型路由

根据用户目的选择最贴近的一类，不强行套用万能模板。各类都应包含版本、状态、范围、非目标、依据、风险和待确认项。

## 架构设计说明书 / 技术方案

最低章节：执行摘要、背景、现状证据、目标与约束、方案比选、架构决策、目标架构、关键流程与状态、组件职责、数据与接口、安全、容量与可靠性、故障恢复、可观测性、实施阶段、测试验收、风险与待决策项。

## 项目总体技术文档

最低章节：项目概述、用户与业务范围、系统边界、技术栈、目录与模块、部署拓扑、核心流程、数据存储、接口集成、环境配置、开发运行、测试现状、发布回滚、运维监控、安全、已知问题、路线图。

## API / 集成文档

最低章节：集成背景、鉴权、环境与基础地址、通用请求/响应、错误模型、幂等与重试、接口清单、逐接口字段与示例、限流、版本兼容、安全、联调步骤、验收用例。

## 数据库 / 数据设计文档

最低章节：数据范围、概念模型、实体关系、表/集合定义、键与约束、索引、事务、一致性、生命周期、迁移、备份恢复、权限、容量、数据质量和验收查询。

## 部署与运维文档

最低章节：目标环境、依赖、网络拓扑、配置与密钥边界、构建产物、部署步骤、健康检查、监控告警、日志、备份、扩缩容、故障处置、回滚、灾备、安全加固和上线检查表。

## 测试方案 / 验收文档

最低章节：质量目标、范围与非范围、环境和数据、功能场景、边界与异常、性能、可靠性、安全、兼容性、自动化策略、缺陷门槛、量化验收标准、上线建议和遗留风险。

## SOP / 操作手册

最低章节：目的、适用角色、前置条件、逐步操作、正常结果、异常分支、禁止事项、回退、检查表、升级路径和修订记录。操作步骤应使用真实编号列表，不把长步骤塞进表格。

## 状态报告 / 技术评审材料

最低章节：结论、当前状态、已完成、证据、未完成、关键风险、阻塞、决策请求、下一阶段和负责人。没有实际负责人信息时写“待指定”。

## 共同证据规则

- “已实现”必须有代码、配置、测试或已验证运行结果支持。
- “建议”“计划”“目标”必须使用将来态，不能与当前态混写。
- 外部事实优先引用官方文档；代码事实优先给出仓库内文件与行号。
- 测试失败、未执行或环境受限必须如实写明。
- 任何密码、令牌、Cookie、私钥和凭据值都不得进入文档。
