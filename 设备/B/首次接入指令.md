# 设备 B 首次接入指令

本文件由根目录 `AGENTS.md` 在新克隆的第一次 Codex 任务中自动调用，不需要用户复制或解释。

1. 完整读取根目录 `README.md`、`AGENTS.md`、四个同步清单和 `设备/B/`。
2. 运行 `./脚本/安装到本机.sh B`，安装本仓库管理的全局规则和个人 Skill。
3. 读取本机 Codex 项目列表，先把清单外可同步项目及其 Git 来源加入项目并集，再与最新项目清单逐项匹配。
4. Windows 上所有共同项目必须放在 `D:\.aaProject-Bruce\`，禁止放到 C 盘；只添加缺失项目，任何现有项目都不删除、不归档、不重命名、不隐藏。
5. 项目代码从清单给出的 Git 仓库取得。来源未就绪时标记阻塞，不创建空壳。
6. 读取本机任务列表，只补充任务清单缺失的长期任务；最近临时对话不复制。
7. 新任务先读取对应上下文，只回复“上下文已导入，等待继续”，不得擅自执行旧任务。
8. 把设备 B 的本地 `projectId`、`threadId` 写入 `设备/B/` 映射；不要复制设备 A 的本地 ID。
9. 使用逻辑 ID 把 `同步清单/侧边栏布局.md` 的共享项目顺序、项目置顶和共同长期任务置顶应用到本机；只用正式 API 或用户可见界面，不直接修改 Codex 原始状态或数据库。
10. 只有全部并集项目真实就绪并完成映射时，才把项目清单记为当前最新版本；任务和侧边栏布局分别记录完整或部分应用版本。运行仓库检查，提交并推送。
11. 最后报告：本机发布的新项目、为本机补齐的项目、原本已存在项、侧边栏布局结果、明确排除项、阻塞项和 Git 推送结果。

## 对齐结果的定义

“完全统一”指除明确排除项外，A、B 最近发布的项目列表并集在两台设备都真实存在并完成映射；长期任务仍以任务清单为准。因此统一过程只做加法，绝不靠删除制造一致。

设备 A、B 只是映射标识，完全平等，不存在主设备、次设备或固定接力顺序。用户会交替使用两台设备；哪台设备被使用，哪台就负责先拉取、继续跟进、及时更新并推送。

首次接入后，设备 B 的 Codex 每次任务开始都先拉取本仓库；共同长期任务产生新上下文时，结束前必须检查、提交并推送。推送失败时明确报告，不得声称已同步。

## 永久排除

`AI学习`、`AI 教学助手`、`AI 笔记助手` 是设备 A 个人内容。设备 B 不读取、不创建、不克隆、不记录为阻塞项。
