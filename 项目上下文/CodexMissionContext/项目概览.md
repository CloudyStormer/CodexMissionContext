# 项目：CodexMissionContext

最近更新：2026-07-30

## 一句话说明

为 A、B 两台设备提供统一的项目、任务、对话语义和个人 Skill 持久化同步。

## 项目目标

- 每项 Codex 任务开始前拉取最新上下文。
- 共同长期任务结束后形成可续接记录并推送 Git；临时对话不自动保存。
- A、B 两台设备平等交替使用，任一设备都能从最新记录继续并及时写回，不设主设备或备用设备。
- 项目代码继续使用各自仓库，本仓库只保存上下文和同步规则。
- 个人 Skill 以本仓库为唯一事实来源。
- 用户发送“项目提交”等主动口令时，按项目列表检查当前设备可访问的全部 Git 仓库并安全提交推送；发送“开始同步”时核对并补齐两端项目并集。

## 已确认决定

- 不同步 Codex 本地数据库、原始 session、认证缓存和运行进程。
- 使用完整语义任务记录代替原始聊天全文。
- 设备 A、B 每次任务开始先拉取；共同长期上下文有变化时，结束前提交并推送。
- 设备 A、B 没有主次关系；用户在两台设备间交替工作，哪台被使用，哪台就负责拉取、跟进、更新和推送。
- Windows 上所有共同项目固定放在 `D:\.aaProject-Bruce\`，禁止放到 C 盘。
- 项目代码不复制进上下文仓库。
- `AI学习` 及其两项任务属于设备 A 个人内容，双设备流程永久忽略，已有内容保留且不删除。
- 新克隆没有 `.device-id` 时，根 `AGENTS.md` 自动按设备 B 首次接入，不要求用户重复说明。
- 公共项目定义为两台设备可同步项目的并集：一端新增项目后必须发布 Git 来源，另一端下次“开始同步”时补齐；通过增加而不是删除实现一致。
- “检查提交”“检查项目”“项目检查”和“项目提交”是独立的用户主动授权：先取得远端状态，再检查项目范围内已有普通改动并分别提交推送；敏感文件、冲突、验证失败和路径违规仍必须阻塞。
- “开始”或“开始同步”主动执行项目并集核对；交班时记录当天工作、新增项目和对方精确待办，推送后尝试通知另一端。
