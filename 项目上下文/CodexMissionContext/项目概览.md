## 已确认决定

- A、B 没有主次关系；哪台设备被使用，哪台就先拉取、继续并及时推送。
- Windows 共同项目只放在 `D:\.aaProject-Bruce\`，不在 C 盘创建共同项目或 worktree。
- 项目代码由各自 Git 仓库管理；本仓库只保存精准压缩上下文、清单、映射和 Skill。
- 日常同步不逐文件研究业务差异，也不提交原任务尚未确认的改动。
- 每台设备的同步与提交统一由一个维护任务直接操作本机各仓库，不再把 Git 动作分派到独立项目任务并逐项要求用户确认；A、B 在同一运行 ID 下各执行一个维护任务不属于逐项目分派。
- “开始同步”是两端同轮、全部共同项目与任务的完整双向同步：若对端维护任务可达则只唤醒一次；两端各自先完成远端取得与安全对齐，再审查、验证、提交和推送安全的本地普通改动，并验证本地与 upstream 一致。
- “开始同步”还必须把两端同步范围任务取并集，在对应已保存项目补齐全部可见镜像，逐任务发送可直接续接的精简语义交接，并验证标题、项目归属、共享顺序和置顶。只有取得同一运行 ID 的两端成功报告，且代码、任务实体、语义和布局全部验证成功，才可声称两端全部同步。真实权限、凭证、冲突、验证失败、敏感内容、业务歧义和离线边界仍须如实登记，禁止强行上传或伪造任务完成。
- 共享布局只保存逻辑 ID 和版本，通过正式 API 或用户可见界面稳定合并；不复制或写入 Codex 原始状态、数据库或 session。
- 每次“开始同步”都在 `同步运行/<运行ID>/` 由 A、B 分别发布本机任务快照，发起端生成唯一合并任务包，两端发送相同正文并用 SHA-256 回执验收；日报不能代替这一运行级交接。
- 完整任务布局使用“完整任务并集迁移”候选分支：先取得 A/B 快照和合并包，再两阶段晋升，最后应用并回读任务正文重算 SHA；发送成功本身不构成内容回执。
- `AI学习`、`AI 教学助手`、`AI 笔记助手` 永久排除，除非用户以后明确改变范围。
