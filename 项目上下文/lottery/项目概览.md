## 产品与技术结构

### 后端

- Python `>=3.10`、FastAPI、Uvicorn、HTTPX、Pydantic、NumPy、SciPy、SQLite。
- 入口：`lottery-calculation-backend/app/main.py`。
- 从体彩、福彩官方接口同步开奖历史。
- 提供健康检查、玩法目录、数据状态、手动同步和候选生成 API。
- 使用卡方均匀性、信息熵、滞后相关和滚动 Brier 损失进行随机性审计。
- 使用 `secrets.SystemRandom` 生成三组等概率候选；7 星彩基本投注已使用 `qxc-coverage-v1` 协调三注，保证七个对应位置均三值互异，把三注任意奖覆盖率提高到 `23.7992%`。

### 前端

- React 18、TypeScript、Vite、Lucide React。
- 入口：`lottery-calculation-frontend/src/main.tsx`。
- 主界面：`lottery-calculation-frontend/src/App.tsx`。
- 通过 `/api/v1` 调用后端。
- 提供发行方、玩法、投注方式选择，并展示概率说明、候选和审计指标。
- 后端目录不可用时使用前端内置回退目录。

### 部署

- 前端仓库中的 `compose.yaml` 假设前后端两个仓库保持当前同级目录结构。
- 前端由 Node 20 构建，Nginx 1.27 托管。
- 后端 Docker 使用 Python 3.12 slim。
- SQLite 通过 Compose 命名卷持久化。

## 不可破坏的业务原则

> 历史开奖只用于审计随机性，不得用于冷热号加权或伪装成预测；候选生成必须保持合法空间内等概率。

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

```bash
cd lottery-calculation-frontend
npm install
npm run dev
npm run typecheck
npm run build
```

```bash
cd lottery-calculation-frontend

```

## 已知风险

1. 福彩抓取固定为 `pageNo=1`、`pageSize=30`，没有分页循环；默认 1200 期及 `full=true` 可能只能取得首批数据。
2. 普通生成在缓存达到 100 期后不再自动刷新，仓库中没有调度器。
3. 同步接口没有认证、限流或后台任务机制。
4. 官方数据解析后没有按玩法验证号码数量、范围、重复和规则版本。
5. 前端初始化失败会被静默忽略，API 请求没有超时、取消、重试或运行时响应校验。
6. 前端回退目录与后端目录重复维护，存在漂移风险。

这些风险是只读检查结论，尚未形成用户授权的整改任务。
