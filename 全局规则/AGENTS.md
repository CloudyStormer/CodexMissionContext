如果当前工作目录是 `/Users/qichao/Documents/AI学习`、`/Users/qichao/Documents/AI 教学助手`、`/Users/qichao/Documents/AI 笔记助手` 中任一项目或其任意子目录，立即停止应用本文件其余规则：


## 每次任务开始

1. 在进行实质性工作前，按当前平台运行：

   macOS：

   ```bash
   ~/Desktop/DEV/Life/CodexSpace/CodexMissionContext/脚本/同步上下文.sh 开始
   ```

   Windows PowerShell：

   ```powershell
   & 'C:\Program Files\Git\bin\bash.exe' 'D:/.aaProject-Bruce/CodexMissionContext/脚本/同步上下文.sh' 开始
   ```

2. 根据当前工作目录确定项目；没有项目时归入“通用”。
3. 读取 `项目上下文/项目索引.md`、对应 `项目概览.md` 和最近相关任务记录。
4. 只把已记录内容视为历史事实；缺失内容必须说明，不能编造。
5. 检查 `同步清单/项目清单.md`、`任务清单.md`、`侧边栏布局.md`、两台设备映射、本设备已应用版本和阻塞项。项目清单采用 A、B 可同步项目的并集；本机发现的新项目必须登记，另一端新增而本机缺失的项目必须补齐。阻塞项即使版本未变化也要重试。
6. 当前项目有独立 Git 仓库时，先检查工作树；干净时取得远端最新版本，存在本地修改时保留并报告，不能覆盖。

## 每次任务进行中

- 保留用户要求、精确数字、日期、文件路径、命令、结果、关键决定、失败经验和能力边界。
- 始终把这些内容整理成可续接的精准压缩总结，不同步原始对话、全量项目内容或重复信息。
- 不把某台设备视为唯一事实来源；以远端最新提交和持久化记录为准，允许下一次从任一设备继续。
- 项目代码仍在项目自己的 Git 仓库中修改和同步。
- 不读取或复制旧对话全文来恢复记忆；优先使用已压缩的任务记录。

## 用户主动项目同步与提交

必须在以下触发下调用并完整遵守 `check-projects` Skill：

- 用户以命令方式发送“检查提交”“检查项目”“项目检查”或“项目提交”：遍历项目列表和当前设备可访问的项目路径，检查每个项目包含的全部 Git 仓库；先取得远端状态，安全改动完成验证后分别提交、对齐并推送。
- 用户单独发送“开始”：同步上下文，核对 A、B 项目并集，登记本机新增项目并补齐另一端已有而本机缺失的项目。
- 用户发送四字口令“开始同步”：执行 `check-projects` 的双端同轮完整同步模式。生成唯一运行 ID，若另一设备维护任务可达则只唤醒一次；A、B 各由一个维护任务刷新本机所有可见共同项目对话、项目并集和共享布局，并分两阶段处理本机全部共同项目 Git 仓库：先 fetch 并安全取得远端提交，再审查、验证、提交和推送安全的本地普通改动，最后逐仓验证本地 `HEAD` 与 upstream 一致并合并两端交接。脏工作树按项目提交流程使用可恢复的保护 stash 安全对齐；冲突、验证失败、敏感内容或不可达来源保留现场并明确报告，其他仓库继续。对端不可达时只能报告当前设备结果。
- 用户要求交接、晚间交班或下班交接：先检查项目提交，再写入并推送当天项目、提交、新增项、阻塞和对方待办，并尝试通知另一端维护任务。
- 这些流程由用户主动触发，不建立定时轮询。“开始同步”遍历所有可见共同项目对话并同步完整语义摘要；临时对话不自动成为共同长期任务。“所有任务”表示走查任务关联代码状态和交接语义，不表示擅自继续未获授权的业务遗留需求；其他模式不遍历无关临时聊天。
- 每台设备只由一个维护同步任务统一处理当前设备的共同项目仓库；B 端仓库仍必须位于 D 盘。A、B 在同一运行 ID 下各执行一个维护任务不属于逐项目分派。不得为了执行 Git 操作而逐项目创建、唤醒或转交独立任务。用户的一次同步或提交口令已经授权对应模式允许的普通 Git 操作，不再逐项目重复确认。若平台仍强制交互授权，先完成无需授权的部分，再把全部阻塞合并为一次说明，不连续发起逐仓审批。
- `AI学习`、`AI 教学助手`、`AI 笔记助手` 继续遵守最高优先级排除；另一台离线设备尚未提交的本地内容不可见，不能声称已经检查。
- 禁止强制推送、覆盖冲突或提交凭证；无法安全处理的仓库保留现场并准确报告，其他独立仓库继续检查。

## 每日集中同步

日常交班只做两类工作：

1. 读取当天可见任务的标题、概述和结果，按项目形成精准压缩总结并推送上下文；不复制原始对话。
2. 对当前侧边栏 D 盘项目做轻量 Git 同步：先取得远端，再只推送已经由原任务确认完成的提交。

不为日常同步逐文件研究业务差异，不代替原任务提交尚未确认的工作。四字口令“开始同步”优先级更高，必须执行所有共同项目“先拉取、再提交推送”和全部共同项目对话语义交接，而不只执行上述日常两项。

## 每次任务结束

1. 只有当前任务已在共同任务清单中，或被用户明确指定为长期任务，才按模板新增或更新任务记录；仅仅属于共同项目并不够，最近临时对话不保存。
2. 只有稳定项目事实发生变化时，才更新对应项目的 `项目概览.md`。
3. 普通任务中，如果项目代码有本任务产生的修改，只处理本任务范围内的文件；运行验证，提交并推送项目自己的 Git 仓库。四字口令“开始同步”和项目提交命令属于明确例外，按 `check-projects` Skill 处理检查范围内已有的普通改动。推送前取得远端更新，禁止强制推送；失败时报告真实状态。
4. 按当前平台运行检查和结束同步。

   macOS：

   ```bash
   ~/Desktop/DEV/Life/CodexSpace/CodexMissionContext/脚本/检查仓库.sh
   ~/Desktop/DEV/Life/CodexSpace/CodexMissionContext/脚本/同步上下文.sh 结束 "项目名：任务简述"
   ```

   Windows PowerShell：

   ```powershell
   & 'C:\Program Files\Git\bin\bash.exe' 'D:/.aaProject-Bruce/CodexMissionContext/脚本/检查仓库.sh'
   & 'C:\Program Files\Git\bin\bash.exe' 'D:/.aaProject-Bruce/CodexMissionContext/脚本/同步上下文.sh' 结束 '项目名：任务简述'
   ```

5. 最终答复必须说明上下文同步是否成功；若失败，给出冲突、网络或权限的真实原因。

## 安全边界

- 永不提交 `auth.json`、`.env`、API Key、访问令牌、密码、Cookie、SSH 私钥、Codex 本地数据库、session、缓存或浏览器登录态。
- 侧边栏布局只持久化逻辑项目/任务 ID、顺序、置顶状态和版本；不得复制或提交 Codex 原始全局状态。应用顺序和置顶必须使用正式 API 或用户可见界面，并以稳定合并保留所有非共享对象的置顶状态和相对顺序；不能保证时只标记部分应用。禁止直接修改本地数据库或全局状态文件。
- 原始运行进程和机器状态不属于 Git 同步范围。
- 项目和任务列表对齐只能增加缺失项。禁止为了统一而删除、归档、重命名或隐藏任何现有项目和任务。
- Windows 设备不得把共同项目克隆、创建或迁移到 C 盘，也不得为共同任务在 C 盘创建 Codex worktree 或项目副本。
- 设备存在清单之外的新项目时，除明确排除项外，将其加入 A、B 项目并集并为另一端提供真实 Git 来源；额外任务仍只保留并报告，除非用户指定为共同长期任务。
