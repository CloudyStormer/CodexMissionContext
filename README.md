# CodexMissionContext

这是 A、B 两台设备共同使用的 Codex 持久化工作记忆仓库。

它解决五件事：

1. 每个需要长期续接的项目都有可持续更新的项目上下文。
2. 共同任务都有独立、可续接的压缩记录；最近临时对话不要求同步。
3. 两台设备在任务开始前拉取、结束后提交并推送最新记录。
4. 个人自制 Skill 通过同一个私有 Git 仓库同步。
5. 用户发送“开始同步”时维护两端项目并集；发送“项目提交”时主动检查全部本地 Git 仓库并安全提交推送。

## 核心原则

> Git 同步项目实体和持久化上下文；任务记录同步完整语义；本地运行状态留在本机。

这里的“完整语义”不是全量复制：无论项目大小，只同步经过整理的精准压缩总结，确保另一台设备能继续工作，同时避免搬运原始对话、整份项目内容和重复信息。

设备 A、B 只是本地映射标识，没有主次关系。用户会在两台设备之间交替工作；任一设备都必须先取得最新上下文，再继续、更新并推送。除明确排除项外，两端共同项目按项目列表并集计算：任一端新增的项目都要登记 Git 来源并补齐到另一端。

Windows 设备上的双设备共同项目统一存放在 `D:\.aaProject-Bruce\`，不得放到 C 盘。

本仓库记录：

- 项目目标、仓库地址、分支和当前提交。
- 用户要求、已确认结论、关键决定及原因。
- 已完成事项、修改文件、命令、测试结果和失败经验。
- 未解决问题、风险、精确下一步和交接指令。
- 个人 Skill 的完整文件。

本仓库禁止记录：

- `auth.json`、访问令牌、API Key、密码、Cookie、SSH 私钥。
- Codex 本地数据库、原始 session 目录、缓存和浏览器登录态。
- 无意义的完整聊天转录。任务记录必须保留完整语义，但要压缩重复表达。
- 项目本身已经由独立 Git 仓库管理的代码副本。

## 每次任务的同步流程

### 开始任务

```bash
./脚本/同步上下文.sh 开始
```

然后依次读取：

1. `项目上下文/项目索引.md`
2. 对应项目的 `项目概览.md`
3. 对应项目最近的任务记录

### 结束任务

1. 只有当前任务已在共同任务清单中，或用户明确指定为长期任务时，才使用模板新增或更新任务记录。共同项目中的临时对话也不自动保存。
2. 只有稳定项目事实发生变化时，才更新对应项目的 `项目概览.md`。
3. 运行检查：

```bash
./脚本/检查仓库.sh
```

4. 提交并推送：

```bash
./脚本/同步上下文.sh 结束 "项目名：任务简述"
```

脚本只有在远端同步、检查和推送都成功时，才会报告完成。出现冲突或网络错误时必须停止并明确报告。

为防止“统一”演变成跨设备误删，自动同步脚本会拒绝本地或远端的删除、重命名；这类变更必须停止并人工核对。

## 主动项目同步与提交

`check-projects` 是第三个个人 Skill，支持：

- “开始”或“开始同步”：读取两台设备已推送的项目映射，以并集为目标补齐本机缺失项目和仓库。
- “检查提交”“检查项目”“项目检查”或“项目提交”：先取得远端状态，再遍历当前项目列表下的全部 Git 仓库；安全改动经验证后分别提交、对齐并推送。
- “交接”或晚间交班：完成项目提交，记录当天工作、新增项目和对方待办，推送后尝试通知另一端。

该功能只由用户主动触发，不检查临时会话，不建立定时任务，也不替代普通任务结束时只处理本任务改动的规则。检查范围限于当前设备可访问的项目；另一台离线设备尚未提交的本地文件无法被远程发现，两端依靠开始同步和交接时推送映射实现最终一致。

## 第二台设备接入

1. 把本仓库克隆到对应平台的固定位置。

macOS：

```bash
git clone git@github.com:CloudyStormer/CodexMissionContext.git ~/Desktop/DEV/Life/CodexSpace/CodexMissionContext
```

Windows PowerShell：

```powershell
git clone git@github.com:CloudyStormer/CodexMissionContext.git 'D:\.aaProject-Bruce\CodexMissionContext'
```

2. 在 Codex2 中打开克隆目录并启动一个任务，哪怕只发送“开始”。
3. 根目录 `AGENTS.md` 会自动进入 Codex 上下文，并直接执行设备 B 首次接入；不需要再粘贴任何说明。

设备标识 A、B 仅用于区分本地 `projectId`、`threadId` 和路径，不表示主设备或备用设备。

设备接入后必须先执行“只增不减”的项目与任务清单对齐。清单外项目进入两端并集，额外任务继续保留但不自动同步；绝不通过删除获得表面一致。

在 Windows 设备上接入时，仓库固定使用 `D:\.aaProject-Bruce\CodexMissionContext`；其他共同项目也必须位于 `D:\.aaProject-Bruce\` 下。

注意：`git clone` 本身只下载文件，不会主动唤醒 Codex。必须在 Codex2 中打开该目录并启动一次任务；从那一刻起，无需额外解释。

仓库新增个人 Skill 后，另一台设备拉取最新提交并再次运行 `脚本/安装到本机.sh A|B`，随后重启 Codex 或新建任务，即可发现新 Skill。
