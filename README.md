# CodexMissionContext

这是 A、B 两台设备共同使用的 Codex 持久化工作记忆仓库。

它解决四件事：

1. 每个需要长期续接的项目都有可持续更新的项目上下文。
2. 共同任务都有独立、可续接的压缩记录；最近临时对话不要求同步。
3. 两台设备在任务开始前拉取、结束后提交并推送最新记录。
4. 个人自制 Skill 通过同一个私有 Git 仓库同步。

## 核心原则

> Git 同步项目实体和持久化上下文；任务记录同步完整语义；本地运行状态留在本机。

本仓库记录：

- 项目目标、仓库地址、分支和当前提交。
- 用户要求、已确认结论、关键决定及原因。
- 已完成事项、修改文件、命令、测试结果和失败经验。
- 未解决问题、风险、精确下一步和交接指令。
- 个人 Skill 的完整文件。

本仓库禁止记录：

- `auth.json`、访问令牌、API Key、密码、Cookie、SSH 私钥。
- Codex 本地数据库、原始 session 目录、缓存和浏览器登录态。
- 无意义的完整聊天转录。任务记录必须保留完整语义，但要压缩重复表达。
- 项目本身已经由独立 Git 仓库管理的代码副本。

## 每次任务的固定流程

### 开始任务

```bash
./脚本/同步上下文.sh 开始
```

然后依次读取：

1. `项目上下文/项目索引.md`
2. 对应项目的 `项目概览.md`
3. 对应项目最近的任务记录

### 结束任务

1. 使用任务模板补充一份任务记录。
2. 更新对应项目的 `项目概览.md`。
3. 运行检查：

```bash
./脚本/检查仓库.sh
```

4. 提交并推送：

```bash
./脚本/同步上下文.sh 结束 "项目名：任务简述"
```

脚本只有在远端同步、检查和推送都成功时，才会报告完成。出现冲突或网络错误时必须停止并明确报告。

## 第二台设备接入

1. 把本仓库克隆到相同位置：

```text
~/Desktop/DEV/Life/CodexSpace/CodexMissionContext
```

2. 运行：

```bash
./脚本/安装到本机.sh B
```

3. 把 [设备 B 首次接入指令](设备/B/首次接入指令.md) 发给另一台设备的 Codex。
4. 重启 Codex 或新建任务。
5. 首次任务先运行 `./脚本/同步上下文.sh 开始`。

当前设备登记为 A；另一台设备预留为 B。

设备接入后必须先执行“只增不减”的项目与任务清单对齐。额外项目和任务全部保留，绝不通过删除获得表面一致。
