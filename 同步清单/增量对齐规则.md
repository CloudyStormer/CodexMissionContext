# 项目和任务列表增量对齐规则

## 目标

让 A、B 两台设备都包含同步清单规定的共同项目和共同任务，同时绝不通过删除现有内容来获得表面一致。

## 一次对齐流程

1. 拉取 `CodexMissionContext` 最新版本。
2. 读取 `项目清单.md`、`任务清单.md` 和当前设备映射。
3. 使用 Codex 项目列表能力读取本机项目。
4. 按“逻辑项目 ID + 显示名称 + 本地路径或远程仓库”匹配。
5. 只添加缺失项目；不能删除、归档、重命名或覆盖已有项目。
6. 读取本机项目任务列表。
7. 只在任务清单规定的项目内补充缺失任务。
8. 新建任务后设置精确标题，并把本地 thread ID 写入设备映射。
9. 只有所有清单项都完成时，才把本设备版本标记为“已完整应用”；存在阻塞时记录“部分应用”、已完成项和待重试项，不得冒充完成。
10. 提交、拉取远端最新变更、解决冲突后推送。

## 阻塞项处理

- 先补齐所有未阻塞项目及其长期任务。
- 项目来源、权限或本地路径未就绪时，保留阻塞状态，不创建空壳。
- 每次任务开始都重试阻塞项，即使清单版本没有变化。
- 阻塞解除并完成全部项目与任务后，才更新为目标清单版本。

## 绝对禁止

- 禁止为了两边一致而删除任何项目或任务。
- 禁止归档额外项目或任务。
- 禁止强制推送覆盖另一设备。
- 禁止把 A 的 projectId/threadId 当成 B 的本地 ID 使用。
- 禁止因路径暂缺而创建无内容的假项目。
- 禁止把最近临时对话批量复制成任务。

## 差异处理

如果 A、B 任一设备存在清单之外的额外项目或任务：

1. 保留原样。
2. 在结果中列出“本机额外项”。
3. 只有用户明确要求把它加入共同集合时，才更新清单。
4. 任何清理动作必须由用户另行明确授权。

## 共同范围缩减

用户明确把项目或任务移出共同清单时：

1. 只更新清单和范围说明。
2. 已有本地项目、任务及历史记录全部保留。
3. 另一台设备不再补建该项，后续同步流程忽略它。
4. 范围缩减绝不构成删除、归档、重命名或隐藏授权。

所以这里的“完全统一”指：

> 同步清单规定的共同集合在两台设备上全部存在；设备自己的额外内容可以保留。

A、B 的本地 `projectId` 和 `threadId` 不要求相同；逻辑 ID、左侧名称、项目归属和持久化上下文必须一致。
