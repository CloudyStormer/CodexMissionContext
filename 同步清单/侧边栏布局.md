## 版本规则

- 当前设备落后于另一端发布版本时，先执行本机基线与未发布变化检查；确认无冲突后再应用远端布局，不发布本机旧布局。
- 只有 `布局状态：有效` 的规范版本可以自动应用；状态为“冲突待裁决”时停止。非零本机基线必须能由设备记录引用的候选快照和摘要重建；无法验证时不得自动覆盖。
- 发布下一版本有两个并列分支：一是当前设备已完整应用最新版本且用户明确调整了可见共享布局；二是发布设备缺少并集对象，但其余可见共享对象已按最新版本验证，缺失对象保持上一版本的置顶区域及其相对每个既有共享对象的前后关系，且没有同基线并发冲突。
- 第二个分支不得借部分视图移动缺失对象；任何相对关系不能唯一保留时停止发布并报告歧义，发布端仍按已部分应用记账。
- 目标设备实际拉取新版本但尚未执行时，由目标设备记为“本设备已确认待应用”；实际尝试后仍缺对象才记为“已部分应用”。发布端只记录“待目标设备获取”，不得替另一端预报收件或应用结果。
- 单纯应用远端版本时不发布由部分视图产生的新版本。
- 部分应用不提升“已完整应用版本”；全部共享对象验证成功后才提升完整版本并清空部分、待应用和未完成状态。
- 应用时保持所有非共享对象的置顶状态及其在各自区域内的相对顺序，只重排共享对象子序列；不能保证时不执行整体重排。
- 同一旧版本被两端并发发布为不同下一版本时停止自动选择并报告冲突。
- 应用远端版本前，若当前可见共享布局已经偏离本设备上次确认的非零基线，也视为未发布本地候选；按 `同步清单/侧边栏布局候选/README.md` 持久化，不能静默覆盖。
- 基线版本 `0` 的首次对齐默认应用远端有效布局；用户明确要求保留本机当前布局时，先保存候选并停止自动应用。
- 新版本必须先单独提交并推送候选，再次 fetch 确认规范仍在前序版本且同基线候选唯一，才在第二个提交中提升为有效规范版本。晋升后才发现迟到的同基线候选时，不回滚已经应用的设备，而把规范状态改为“冲突待裁决”并暂停其他设备继续应用。
- 应用排序和置顶只能使用正式 Codex API 或用户可见界面；严禁直接写 Codex 原始状态或数据库。
