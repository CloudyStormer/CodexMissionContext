## “开始同步”的任务完成标准

除明确排除项外，所有属于共同项目的可见任务都进入本清单，不再区分“长期任务”和“临时任务”。每个逻辑任务必须：

1. 在 A、B 对应的已保存项目中各有一个可见任务；本地 `threadId` 可以不同。
2. 标题、逻辑项目、置顶状态和共享子序列一致。
3. 镜像任务内至少有一条精简交接消息，保留用户要求、结论、决定原因、相关文件与命令、验证、失败、边界、风险、遗留问题和下一步；不复制原始聊天全文。
4. 新建镜像只导入上下文并等待用户继续，不擅自执行旧需求。
5. 只用正式 Codex API 或用户可见界面创建、置顶和排序；能力缺失时记为阻塞，不伪造完成。
6. A、B 对同一逻辑任务使用 `完全对齐交接包.md` 规定的同一版规范化语义正文；双端回执中的正文 SHA-256 必须一致。

仅当本清单所有非排除任务在两端均可见、语义交接已送达且布局已验证，才可声称“侧边栏与对话已同步”。

## 精简对话镜像规则

- 原始逐字消息、附件缓存、账号状态、数据库和 session 不复制。
- 同一逻辑任务的镜像消息使用稳定结构：`当前目标 / 已完成 / 关键决定与原因 / 文件与命令 / 验证 / 失败与风险 / 下一步 / 原设备与更新时间`。
- 每次“开始同步”先读两端最新摘要，分别写入 A/B 任务快照；发起端按任务 ID 生成唯一合并任务包，规范化正文并计算 SHA-256，再把完全相同的正文发送到两端任务；不能只写每日总报告。
- 历史记录已经足够且本轮没有新语义时，只记录“已核对、无新增”，不重复堆叠全文。

## 明确排除

- `AI学习`、`AI 教学助手`、`AI 笔记助手` 及其任务：设备 A 个人内容，设备 B 不读取、不创建、不作为阻塞。
- 普通 ChatGPT 云对话、项目外 C 盘个人问答、自动化任务和没有发送消息的空白任务。
- 用户以后明确移出同步范围的对象；已存在项仍保留，不删除、归档、重命名或隐藏。

## 镜像创建规则

1. 先让逻辑项目在目标设备以真实项目根存在，并通过正式项目列表回读 `projectId`；Windows 设备根目录必须在 `D:\.aaProject-Bruce\`，设备 A 使用其已登记的 macOS 路径。
2. 用标题、逻辑项目和既有映射判重；同名但不同项目是不同逻辑任务。
3. 缺失时在对应已保存项目下创建任务，设置精确标题，并发送合并后的精简交接消息；随后回读正式任务列表，确认任务实际可见且标题、项目归属正确。
4. 把目标设备真实 `threadId` 写入其任务映射；不得复制另一设备的本地 ID。
5. 若没有添加项目、创建任务、排序或置顶能力，保留阻塞并继续其他可执行项；可见任务暂时无法映射到逻辑项目时也必须登记为待判定阻塞，禁止静默排除或把任务建到错误项目、projectless 或 C 盘副本中冒充完成。
